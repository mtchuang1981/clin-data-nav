# Clinical Data Research Navigator v0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a locally verified `v0.3.0` candidate that gives beginners a short first success, selects one of four safe output depths, provides complete deterministic Eval evidence, and proves byte-identical Windows/Linux packages without crossing the separately approved GitHub publication boundary.

**Architecture:** Keep one installable GitHub-hosted Agent Skill and add a small output-depth router in its instruction contract. Put beginner education in bilingual repository docs plus one packaged reference, derive Eval evidence from the catalog and fixtures, and centralize package-directory comparison in one standard-library CLI used by both CI workflows. Preserve the guarded Release writer as an artifact-only boundary with no checkout or repository-code execution.

**Tech Stack:** Markdown, YAML, Python 3.11, pytest, PyYAML, deterministic ZIP/JSON manifests, GitHub Actions, PowerShell, POSIX shell, GitHub CLI.

## Global Constraints

- Execute from the commit containing this plan and the approved design
  `docs/superpowers/specs/2026-08-02-v0.3.0-new-user-experience-design.md`
  in an isolated worktree created with `superpowers:using-git-worktrees`.
- Support exactly Python `>=3.11,<3.12`; do not make Python a runtime dependency
  for using the installed instruction-only Skill.
- Preserve all 222 baseline tests; do not delete, skip, xfail, or weaken a test
  to get green. The final test count must be greater than 222.
- Add or update a failing test before every behavior, schema, workflow, or
  version change. Documentation-only prose may use contract tests written first.
- Use only synthetic institutional examples. Do not read or copy private
  adapters, codingbooks, data dictionaries, physical schemas, linkage rules,
  PII classifications, internal guides, or version-specific metadata.
- Keep safety, evidence authority, uncertainty, public/private boundary, and
  execution-gate rules global across all four output depths.
- Use the exact public output-depth labels `quick explanation`,
  `evidence navigation`, `research design`, and `implementation specification`.
- Retain the 11 existing Eval case IDs, add exactly
  `adam-quick-explanation`, and require all 12 cases to have one baseline and
  one forward fixture.
- Keep the fixed Eval pass threshold at 100. Every baseline must score below
  100; every forward fixture must score at least 100 and trigger no forbidden
  rule.
- Compare ZIP and manifest bytes from Ubuntu and Windows. Missing, extra,
  renamed, nested, or byte-mismatched files must fail closed.
- Pin every official GitHub Action to a verified full commit SHA and keep a
  human-readable release comment. All jobs remain `contents: read` except the

  meaning and navigation. Use Taiwan Traditional Chinese terminology.
- Synchronize current release surfaces to `0.3.0`; preserve historical
  changelog entries, release notes, verification records, tags, and URLs.
- Do not invent a maintainer legal name, affiliation, email, ORCID, DOI,
  Zenodo record, icon, or decorative metadata.
- Do not claim this repository is listed in a public Plugin directory. Official
  OpenAI documentation describes Skills as reusable-workflow authoring format
  and Plugins as a separate distribution package.
- Keep `.baoyu-skills/baoyu-translate/EXTEND.md` and all unrelated local-tool
