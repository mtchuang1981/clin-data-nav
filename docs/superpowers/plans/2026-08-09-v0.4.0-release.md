# Clinical Data Research Navigator v0.4.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the reviewed v0.4.0 effectiveness-evaluation framework through a new annotated tag and the repository's guarded GitHub Release workflow, then independently verify and record the public assets.

**Architecture:** First create and verify a release-preparation commit that synchronizes all active version surfaces while preserving historical releases. Tag only the fully verified main commit; let the guarded workflow rebuild on Ubuntu and Windows, compare byte-identical candidates, and create the immutable Release. Verify the public assets from a fresh download and commit post-release evidence without moving the published tag.

**Tech Stack:** Python 3.11, pytest, PyYAML, deterministic ZIP/JSON manifests, Git, GitHub CLI, GitHub Actions, PowerShell, SHA-256.

## Global Constraints

- Target version and annotated tag are exactly `0.4.0` and `v0.4.0`.
- Publication date is `2026-08-09` in `Asia/Taipei`.
- Preserve all historical changelog sections, release notes, tags, Releases, verification records, and asset URLs.
- Release assets are exactly `clinical-data-research-navigator-0.4.0.zip` and `clinical-data-research-navigator-0.4.0.manifest.json`.
- Do not claim a human pilot, real participant data, clinical validity, or proven effectiveness.
- Do not include private adapters, condition keys, private task packs, PII, or free-text participant material.
- Never force-move or recreate `v0.4.0`; never overwrite or edit an existing v0.4.0 Release.
- Any test, gate, CI, tag, workflow, asset-list, or digest mismatch stops publication.
- The final GitHub writer remains the existing guarded workflow; do not publish assets with a local `gh release create` command.
- Use the official temporary Python 3.11.9 runtime at `C:\tmp\python-3.11.9-embed-amd64\python.exe` after confirming `--version` and its configured repository path.
