## Root cause and tests

The initial new/overwrite native tests both failed on the old installer: the
installed tree lacked the selected destination's authenticated-reader ACE.
The private tempfile ACL was retained in the moved tree. The fix copies only
the destination DACL to the installer-owned empty temporary container before
creating/extracting staged children. It does not modify the destination policy,
copy owners/SACLs, grant fixed principals, or change atomic rename/rollback.

Native tests cover both new and overwrite installs, failure before old-target
mutation, non-Windows no-op, eight direct-reference ACL policy comparisons
(OICI, NO_PROPAGATE, OI-only, non-inheritable; explicit/inherited parents), and
get/set/null-DACL error cleanup. Strict raw SDDL equality initially flagged only
the AI bookkeeping control bit. Per Microsoft SDDL documentation, tests now
normalize only the exact D:AI prefix, retaining every ACE/flag/order/right and
the significant protected/AR controls. All 72 installer tests passed on
Windows/Python 3.13.13. This extra runtime probe does not broaden the supported
Python range (3.11). A fresh independent reviewer reported no concrete issue
after reviewing the implementation and added policy/error tests.
