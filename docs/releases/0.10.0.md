Preparation date: 2026-10-19; local candidate, **not published**.

## English

### Candidate capabilities

- Optional generic institutional contract revision 1.2 routes an approved,
  in-scope compiler capability through resolve_concept, validate_spec,
  compile_spec and run_fixture_test. Manifest schema 1 and capability version 1
  are independent of the package version and OMOP wire contracts.
- The new pure helper validates only the closed capability declaration. It
  performs no I/O, compiler work, tool discovery or maturity promotion.
- Concept provenance, complete parameters, current metadata, exact accepted
  specification and tested program digests, authorized fixtures, expected
  results, and independent execution/disclosure authority remain required.
  Generated programs are not hand-edited; private artifacts stay local by default.
- Feasibility scoping separates logical requirements from execution permission;
  an unstated index event becomes a reasoned proposal pending confirmation.
- Carry forward opt-in OMOP 1.1/1.2 DQD evidence and explicit age-policy support
  since v0.9.0. DQD acceptance never overrides structural incompatibility;
  this metadata-only connector is not a compiler or real-data execution API.

### Verification and claim boundary

Six synthetic regression cases use the existing evaluator in a separate suite.
Historic benchmark inputs, thresholds and conclusions remain unchanged. A fixed
ten-answer guided probe observed index proposals in 5/5 candidate versus 0/5
baseline answers; both arms preserved the tested safety boundaries. This is not
proof of safety improvement, adversarial robustness or human effectiveness.

No private compiler, private tool mapping, institutional conformance, human
effectiveness, clinical validity or real-data execution was verified. Local
checks do not establish Windows/Ubuntu CI equality or public release assets.
The previous intermittent Windows cleanup failure remains unexplained, not
fixed. Publication remains blocked; see the aggregate
[verification record](../verification/2026-10-19-governed-compiler-pipeline.md).

## 繁體中文

### 候選版功能

- 通用機構契約修訂 1.2 新增選用的受治理編譯路由；四個邏輯操作必須有
  經核准且適用的本機映射與授權。manifest schema 1、能力版本 1、OMOP
  wire 契約與套件版本各自獨立，不可混用。
- 純驗證函式只檢查封閉的能力宣告，不讀檔、不呼叫工具、不實作編譯器，
  也不判定或提升成熟度。
- 保留概念來源、完整參數、現行 metadata、確切規格／程式雜湊、經授權的
  fixture 與預期結果，以及獨立的執行／揭露許可。不得手改產出程式；
  私有產物預設留在本機，模型接收前就必須完成最小化與揭露控制。
- 可行性計數先交付邏輯需求；未指定 index event 時，提出具理由且待確認
  的建議，不自行當成已核准研究定義或執行權限。
- 納入 v0.9.0 後的 OMOP 1.1／1.2 DQD 證據與明確期限政策支援。
  DQD 採信不覆寫結構不相容；唯讀 metadata connector 並非編譯或執行 API。
